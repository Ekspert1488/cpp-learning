## Скрипты в хронологическом порядке:
 В папке scripts находятся все необходимые скрипты для создания фрагментов и загрузки их в config AiDTA (нейросеть, которая предсказывает нам аптамеры, конфиг находится в той же папке со скриптами)
 1. Enumerate_nucl.py  - скрипт, созданный как библиотека небольших функций по созданию папочек, началу докинга и сортировки. Далее из него лишь пару функций заимствуются для других скриптов.
 2. run_mass_build.py -  Запускает сборку pdb файлов нуклеотидных фрагментов через NSP библиотеки 3D_DNA. На выход получаем файл build_results.csv -  таблица, где параметры используются для отладки: 
    **Name** : название, ss -  значит одинарная цепь ДНК , ds - дуплекс;
    **OK** : Булевое значение прошел ли процесс успешно;
    **kind** ss;ds - одинарные цепи и дуплексы соотвественно;
    **L**: длина нуклеотидной цепи;
    **charge**: посчитанный заряд - один из главных критериев, что цепь в pdb разрезана верно. 
    **expected**: Ожидаемый заряд.Заряд должен быть равен **-(L-1)** для ss цепей и **-2(L - 1)** для ds;
    **ret**: код возврата внешней команды;
    **reason**: текст ошибки, если ok = True , то все пусто;
    **src**: Инструмент, с помощью которого происходила сборка. 3-4 нт собирал tleap (NSP не умеет настолько малые цепи), остальное NSP.
    **seconds**: Время в секундах от начала прогона.
3. clean_ter.py - Заменен на normalize.pdb, использовался для исправления pdb файлов из-за ошибки разрезания цепи на несколько. Большинство проблем решается с помощью normalize_pdb.py.
4. normalize_pdb.py - Самый действенный скрипт, чинящий 3д структуры фрагментов. Достаточно грубый, но в массовом прогоне полезный.
5. repair_ds.py -  чинит разломы исключительно в ds цепях, "дочищает" за normalize_pdb.py 
6. dock_all.py -  Запуск массового докинга HDOCKlite.  На выходе получаем файл **scores_H.csv** - таблица, где указаны данные параметры: 
    **Name** - имя фрагмента;
    **kind** - тип фрагмента: ss или ds;
    **L** - длина фрагмента;
    **src** - Инструмент, с помощью которого получена 3д структура фрагмента. 
    Есть **nsp** -  стандартный NSP,  и **rebuild-ds** - починка с помощью **rebuild_539.py**, и **rebuild-ss-fb**;
    **score_extra** -   лучший score докинга для тех положений, чье минимальное расстояние до внеклеточной части меньше 7 ангстрем(чем меньше тем больше вероятность связывания);
    **dist_extra** -  минимальное расстояние между атомами  внеклеточной части рецептора и фрагмента в ангстремах;
    **n_near_extra** - количество  положений из **n_max** = 100, которые были "связаны"(минимальное расстояние не более 7 ангстрем) с внеклеточной частью рецептора;
    **score_epi** - лучший score докинга для тех положений, чье минимальное расстояние до эпитопа меньше 7 ангстрем.;
    **dist_epi** -  минимальное расстояние между атомами  эпитопа рецептора и фрагмента в ангстремах;
    **n_near_epi** - количество  положений из **n_max** = 100, которые были "связаны"(минимальное расстояние не более 7 ангстрем) с эпитопом рецептора;

7. rebuild_539.py - Перезапускает сборку структур фрагментов.ambpdb в AmberClassic не понимает флаг -c: печатает 101 байт заголовка и выходит с кодом 0 . Затронуто 539 моделей (320 ss L3–L4 + 219 ds). Исправлено заменой на ambpdb -p prmtop < min.rst..Дозаписывает в **scores_H.csv** с тегом в src - **rebuild_ds**.
8. select_top.py -  Выбирает из score_H.csv лучшие фрагмента каждого типа и каждого размера по 5 штук. То есть приоритет одается **score_epi**, затем **dist_epi**, и в последнюю очередь **n_near_epi**. Лично я делал вручную в эксель табличке округляя до десятков. Поскольку считаю, что погрешность "чернового" докинга такова, что это допустимо. Сортировка делалась по такому же алгоритму.
 В итоге 40 лучших фрагментов вместе с вторичной структурой помещаются в конфиг **AiDTA**: в папке **Config_AiDTA/config_A2A_AiDTA.py**.

## Параметры сборки и докинга
 ### NSP_frag (Потребляет вторичную структуру)   
    
    _version 2.0.0
    _lib_version 3dRNA-Lib1
    name ds_AAAAAA - нужно название
    seq AAAAAA&TTTTTT - буквенная структура
    ss ((((((&)))))) - вторичная структура
    num 1
    num_samplings 1
    _minimize yes - минимизация выполняется
    _pred_ss no - использует указанную нами вторичную структуру
    loop_building partial_bires
    _mol_type dna
    _rna_type linear
    _routine Default
    
                                                             
    imin   = 1,                                                                  
    ntxo   = 1,                                                                  
    maxcyc = 1000, - количество циклов минимизации.                                                                 
    ncyc   = 500,  - переключение алгоритма                                                              
    ntb    = 0,                                                                  
    igb    = 5, - GB-OBC II, неявный растворитель                                                               
    cut    = 12, - отсечка невалентных, то есть взаимодействий на расстоянии более 12 ангстрем.
    Potential function:
     ntf     =       1, ntb     =       0, igb     =       5, nsnb    =       1
     ipol    =       0, gbsa    =       0, iesp    =       0
     dielc   =   1.00000, cut     =  12.00000, intdiel =   1.00000
     saltcon =   0.00000, offset  =   0.09000, gbalpha=    1.00000
     gbbeta  =   0.80000, gbgamma =   4.85000, surften =   0.00500
     rdt     =   0.00000, rgbmax  =  25.00000  extdiel =  78.50000 - диэлектрическая проницаемость
     alpb  =        0
     Метод минимизации:
     LMOD:
     xmin_method                  = LBFGS
     lbfgs_memory_depth           =       3
     matrix_vector_product_method = forward finite difference
     xmin_verbosity               =       0
    source leaprc.DNA.OL15 - Поле

 ### Hdock
    Grid spacing:     1.200 - шаг сетки в ангстрем
    Angle step:    15.000 - шаг угла в градусах
    Initial rotation:     0.00000   0.00000   0.00000 - начальный поворот
    На вход Hdock подаем pdb файл фрагмента и рецептора. На выходе получаем около 4000 различных положений лиганда и данный ему score в job.out.
